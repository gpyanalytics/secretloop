# 0007 — 0.7.0 release scope: containment reach, support statement, release gate

**Status:** adopted for 0.7.0 (2026-10-04). **Surfaces:** CLI, VS Code, MCP; release process.

## Decisions

Recorded by the owner on 2026-10-04 against the candidate built from `main`
`f38ea4a060b3e3e7a027d12e201a69971e338abe`:

- **D1 — containment reach.** 0.7.0 ships containment route (a) only: identity
  capture on every content descriptor on every platform, the Linux kernel-path
  check before the first read, and the Linux post-read repeat. **N4**, the macOS
  kernel-path equivalent through in-box `lsof`, is **deferred from 0.7.0**; the
  current macOS limitation (identity check only, kernel path `unavailable`) is
  preserved and documented as such. **N5**, the `node:wasi` containment
  evaluation, is **not funded for this release** and stays a backlog evaluation.
- **D3 — Windows support statement.** The statement already published in
  `SECURITY.md` and the docs — the validated set (x64 and ARM64 hosted images,
  NTFS, one exFAT volume refused as designed), the unvalidated list (FAT32, ReFS,
  network volumes, domain and managed profiles, non-English hosts) and the
  conservative compatibility refusals — **is** the 0.7.0 support statement.
- **D4 — branch protection.** Unchanged. `main` requires `self-scan`,
  `packaging`, `test (18)` and `test (20)`; the macOS, Windows, ARM64 and exFAT
  jobs run on every push and pull request but are not required contexts.
- **D5 — release gate.** Every job of the CI workflow must succeed on the exact
  release pull request and on the push-to-`main` commit it produces before
  anything is published. A failure, timeout or cancellation is investigated and
  recorded; a run is not repeated solely to obtain a green result. This is a
  manual requirement in `RELEASING.md` §7, not a change to branch protection or
  to the workflow.

## Why

Area D's four guarantees are not degrees of one thing (release reconciliation,
§4). Route (a) is measured on Linux; the macOS route needs a per-file spawn whose
cost is bounded but unmeasured in CI, and `node:wasi` has no written answer yet.
Shipping 0.7.0 on route (a) with the limitation stated is preferred to holding the
consent-store and schema work behind an unfunded evaluation. D5 widens the gate
because the matrix now carries the only evidence for ARM64, macOS and exFAT
behaviour, none of it a required check.

## What it costs, stated

On macOS and Windows an object moved under the root after the open and before the
check is read; the Linux-only post-read check does not exist there. A red
non-required job on the candidate now blocks publication where it previously
blocked only if it was one of the two named Windows jobs.
